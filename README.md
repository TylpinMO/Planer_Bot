# Planer Bot

Telegram-планировщик на Python: списки задач, отметки выполнения и напоминания с учётом часового пояса.

## Возможности

- Асинхронные обработчики aiogram и многошаговые диалоги через FSM.
- Пользователи, списки, задачи и подписки в SQLAlchemy; SQLite для локального запуска.
- Напоминания для списков, индивидуальные уведомления и ежедневная сводка через APScheduler.
- Проверка владельца задачи и списка при изменениях.
- Модуль подписки через Telegram Stars и административные команды.

## Запуск

Проверяемая версия окружения — Python 3.12.

```bash
git clone https://github.com/TylpinMO/Planer_Bot.git
cd Planer_Bot
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В Windows используйте `.venv\Scripts\Activate.ps1` и `Copy-Item .env.example .env`.

В `.env` укажите свой `BOT_TOKEN` и `ADMIN_IDS`. Токен создаётся через BotFather; идентификаторы администраторов разделяются запятыми. Для локального запуска оставьте SQLite в `DATABASE_URL`.

```bash
python main.py
```

При первом запуске создаются таблицы БД. Не запускайте второй polling-процесс с тем же токеном.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты работают без Telegram-токена и сетевых запросов: используют временную БД SQLite и подменяют обращения к Telegram. Проверяются операции с задачами, разделение пользовательских списков, контроль доступа, продление подписки и инициализация приложения. GitHub Actions запускает их на Linux и Windows.

## Структура

- `bot/handlers/` — команды, callbacks и диалоги.
- `bot/middlewares/` — сессия БД, пользователь и статус подписки.
- `database/` — модели и операции с данными.
- `services/` — напоминания и параметры платежей.
- `tests/` — автоматические проверки.

## Границы проверки

Это исходный код проекта, а не публичный работающий бот. Оплата настоящими Stars, доставка уведомлений и PostgreSQL не проверяются в CI. Перед рабочим запуском нужны отдельный тестовый бот, проверка платежного сценария и резервное копирование БД. Часовые пояса заданы целочисленным смещением UTC, без перехода на летнее время.

Не добавляйте в Git `.env`, базы пользователей и логи. Скрипты развёртывания рассчитаны на Linux; пути и имя службы нужно проверить перед использованием.
